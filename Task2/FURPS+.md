| **F** | **Функциональные (Functionality)** | |
| F1 | На **сайте** клиент видит перечень депозитных продуктов с актуальными ставками и может подать заявку, указав Ф. И. О. и телефон. | Базовая воронка для новых клиентов. |
| F2 | Заявка с сайта автоматически создаётся в системе кол-центра; оператор видит её карточку, может фиксировать «специальную» ставку и результат звонка. | Интеграция сайта ↔ кол-центра. |
| F3 | В **интернет-банке** авторизованный клиент видит персональные ставки, выбирает счёт-источник и сумму, создаёт заявку и подтверждает её SMS-кодом. | СМС-подтверждение реализуем силами команды банка, не трогая ядро подрядчика. |
| F4 | Система ставок (новый модуль) хранит истории расчётов ставок и обеспечивает совместную работу бэк-офиса депозитов и кредитов. | Уходим от Excel, упрощаем процессы. |
| F5 | После подтверждения ставки и после открытия депозита клиент получает SMS-уведомления. | Используем существующий SMS-шлюз. |
| F6 | Менеджер бэк-офиса подтверждает условия депозита в АБС; запись о депозите создаётся в АБС автоматически. | На этапе MVP бэк-офис остаётся в процессе. |
| F7 [NEW] | Логи заявок, SMS и ошибок доступны в единой панели мониторинга. | Позволяет поддерживать SLA и упрощает эксплуатацию. |
| **U** | **Удобство использования (Usability)** | |
| U1 | Все веб-интерфейсы соответствуют корпоративной дизайн-системе (цвета, шрифты, бренд-элементы). | Сохраняем целостность пользовательского опыта. |
| U2 [NEW] | Время визуального отклика UI (First Contentful Paint) ≤ 1 с при 95-м персентиле. | Чёткая метрика для UX. |
| U3 [NEW] | Подача заявки и подтверждение SMS занимают ≤ 3 экрана/шага. | Минимизируем когнитивную нагрузку. |
| U4 [NEW] | Интерфейсы соответствуют WCAG 2.1 AA (кнопки ≥ 44 × 44 px, контраст ≥ 4.5 : 1). | Удобно как пожилым, так и молодым клиентам. |
| **R** | **Надёжность (Reliability)** | |
| R1 | Доступность сайта и интернет-банка — **99,9 %** (недоступность ≤ 8 ч 45 м в год). | Цель бизнеса — доверие к онлайн-каналам. |
| R2 | Сервисы работают 24 × 7; при падении основного ЦОД выполняется переключение на резервный ≤ 15 мин (RTO) с потерей данных ≤ 5 мин (RPO). | Опираемся на имеющийся резервный ЦОД. |
| R3 [NEW] | SMS-уведомления доставляются не более чем с двумя автоматическими ретраями; при недоставке клиент информируется по e-mail. | Повышаем надёжность коммуникаций. |
| **P** | **Производительность (Performance)** | |
| P1 [NEW] | Время ответа backend-API ключевых операций ≤ 200 мс при 95-м персентиле. | Стабильный UX и база для масштабирования. |
| P2 [NEW] | Решение масштабируется горизонтально и обрабатывает ≥ 100 TPS заявок в пике без деградации SLA. | Рост после запуска маркетинговых кампаний. |
| P3 [NEW] | Балансировщики распределяют нагрузку между ЦОД-ами в актив-актив режиме. | Учитывает требование 24/7. |
| **S** | **Поддерживаемость (Supportability)** | |
| S1 | Используются стеки, в которых уже есть экспертиза: ASP.NET / C#, Java Spring Boot, React, MS SQL, Oracle. | Снижает риск и время обучения. |
| S2 [NEW] | Внедряются автоматические unit-, integration- и E2E-тесты; покрытие критического кода ≥ 70 %. | Ускоряет релизы и снижает дефекты. |
| S3 [NEW] | Все новые сервисы описываются в OpenAPI 3.0; документация публикуется в корпоративном портале. | Требование бизнеса к дальнейшему расширению (кредиты и др.). |
| S4 [NEW] | Для межсервисного обмена сообщений используется Kafka (при необходимости очереди). | Стратегический стандарт банка. |
| **+R** | **Ограничения (Restrictions)** | |
| +R1 | Новые БД — только MS SQL или Oracle; использование других СУБД требует одобрения архитектора банка. | Совместимость с экосистемой и лицензиями. |
| +R2 [NEW] | Фронтенд сайта разворачивается в существующем PHP+React окружении; интернет-банк остаётся на ASP.NET MVC 4.5 в MVP. | Ограничение по срокам и бюджету. |
| +R3 | Интернет-банк не обращается к АБС напрямую; используется отдельный сервис-шлюз или шина для разгрузки АБС. | Снимает риск перегрузки Oracle БД. |
| +R4 [NEW] | При проектировании микросервисов следует предусмотреть совместимость с текущей версией интернет-банка, не поддерживающей Kafka напрямую (шаблон Outbox / gateway). | Позволяет двигаться к целевой архитектуре поэтапно. |
| +R5 [NEW] | АБС масштабируется только вертикально; архитектура новых сервисов должна компенсировать это (кэширование, асинхронные очереди). | Техническое ограничение исторической системы. |
